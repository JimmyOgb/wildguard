          Zero-Trust Guardrail Policies
        

        
      

      

        

          
1. Path Containment & Traversal Defense

          

            All file reads and patch writes are strictly resolved against the repository root. Traversal tokens (..), UNC shares (//share), and symlink breakouts are rejected with hard blocks.
          

        

        

          
2. Secret & Credential Redaction

          

            Files matching .env*, id_rsa, *.pem, *.key, and credential stores are blocked from being read or listed, preventing model context leaks.
          

        

        

          
3. Protected Branch Immutability

          

            Direct writes to main and master are blocked at the engine level. Agents can only propose patches to feature branches (feat/*).
          

        

        

          
4. Human Approval Dependency Gate

          

            Alterations to package.json, package-lock.json, or build configurations demand explicit operator sign-off before being applied to disk.
          

        

      

      

        Deterministic engine rules supersede model suggestions and cannot be disabled via UI.
